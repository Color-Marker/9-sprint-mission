* 애초에 지금 id를 구분자로 거의 쓰고 있으니, key를 id로 두는 방식도 좋았을 것 같음.
* 근데 지금 와서 바꾸기엔 너무 많은 코드를 바꿔야 할 거 같음...

## 3. 가독성 없는 메인 코드
* 한 파일에 모든 코드를 적는 안 좋은 버릇이 있음.
* 나름대로 객체 지향이니까 일부러라도 메소드 많이 나눠서 만들면 되지 않을까 하고 만들어본건데 이렇게 하는 게 아닌 거 같음...
* 그렇다 보니 메인이 있는 workTest 클래스에 main 말고도 정말 많은 메소드들이 들어가 있음.
* 찾아보면 반복되는 부분들도 많은데 그걸따로 빼서 메소드로 만들어 두지도 않음.
* user관련, server관련, channel관련, message관련 메소드들을 따로 클래스로 빼서 만들었으면 조금 더 깔끔하지 않았을까 싶음.

## 4. 예외처리 안함! 
* try catch 구문을 안 씀!
* 이것도 나쁜 버릇인데 일단 작동 확인해보고 에러나면 원인 확인하고 if로 처리해버림.
* 이러니 에러나는 경우에 따라 if를 다 따로 만들다 보니 코드는 길어지고 가독성도 나빠짐.
* 예상치 못한 에러에 대해서 해결을 못함.
* Exception이 종류가 정말 많던데 뭘 써야할지 모르겠음.
* 사실 예외 발생 시 throw를 써야 할 거 같긴 한데, throw는 하면 프로그램이 종료되어 버리다 보니, 그게 싫어서 그냥 전부 print로 적었음
* 그래도 공부해보는 건데 throw 방식으로 해보는 게 좋았을까 싶음.
